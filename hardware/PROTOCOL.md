# 串口协议（PC 桥 ↔ ESP32-C6）

PC 端 `bridge/serial-bridge.js` 与固件 `firmware/agent-leds/agent-leds.ino` **共同遵守本文件**。改协议先改这里。

## 物理层

- **波特率**：`115200`
- **方向**：单向，PC → ESP32（ESP32 只读不回）。可选 ESP32 启动时打印一行 `READY`（仅调试，PC 侧忽略）。
- **编码**：ASCII 文本，行尾 `\n`（`0x0A`）。好调试——Arduino 串口监视器可直接手打。

## 帧格式

一帧 = 4 组 RGB + 可选活跃度段。组间用 `;` 分隔，组内 R,G,B 用 `,` 分隔；
活跃度段跟在全部 RGB 组之后，用 `|` 引出、逗号分隔；整帧以 `\n` 结尾：

```
R,G,B;R,G,B;R,G,B;R,G,B|A0,A1,A2,A3\n
```

- **RGB 段**：固定 **4 组**（对应 4 颗 RGB LED，第 1 组 = LED0，最活跃的 agent）。
  每个分量是 `0..255` 的十进制整数。空槽（无 agent）= `0,0,0`（灭）。
- **活跃度段**（`|` 之后，可选）：`A0..A3` = 各槽“活跃度” `0..255`，越活跃越大
  （`ageSec` 越小 → 越接近 255）。供指针表头等**模拟连续输出**用；RGB 只能表达离散状态。
  空槽 = `0`。段数与 RGB 组一致。

**示例**：第 1 颗绿（WORKING，很活跃）、第 2 颗橙（WAITING，中等）、其余灭：

```
0,200,0;255,80,0;0,0,0;0,0,0|250,120,0,0
```

### 向后兼容（旧固件忽略活跃度段）

只解析 `;` 组和 `\n` 的旧固件（如 `firmware/agent-leds/`，ESP32-C6，无表头）**不受影响**：
它取最后一组 B 分量时用 `String::toInt()`，而 `toInt()`（底层 `atol`）**解析前导数字、遇 `|` 即停**，
所以最后一组的 B 值不被污染，`|` 及其后内容被整体忽略。老硬件插上照常只点灯。

> 这条“遇非数字即停”是本兼容方案的隐式契约。若换用严格整解析（如 `strtol` 校验尾字符），需另行处理 `|`。

## 状态 → RGB 映射（唯一真相源）

PC 桥按会话 `state` 查此表；空槽用 EMPTY。固件不认识状态，只收 RGB。

| state     | 含义         | R   | G   | B   | 颜色 |
|-----------|--------------|-----|-----|-----|------|
| WORKING   | 正在运行     | 0   | 200 | 0   | 绿   |
| WAITING   | 等你确认     | 255 | 80  | 0   | 橙   |
| DONE      | 本轮已回复   | 0   | 120 | 200 | 青   |
| RECENT    | 近期活动     | 200 | 160 | 0   | 黄   |
| (EMPTY)   | 无 agent     | 0   | 0   | 0   | 灭   |

> 数值偏低是为了限流 + 避免刺眼；可在固件端整体缩放亮度。

## 槽位规则

- `scan()` 返回的行已按 `ageSec` 升序（最活跃在前，见 `core/scanner.js`）。
- 桥取前 **4** 个，依次填 LED0..LED3；不足 4 个的槽填 `0,0,0`。
- 超过 4 个的 agent 不显示（4 颗灯的物理上限）。

## 容错

- 固件对**畸形帧**（分量缺失/越界/组数≠4）应整帧丢弃，保持上一帧，不闪。
- 桥在 `state` 出现未知值时按 EMPTY（灭）处理，不崩。
